# P1: tracking ephemeris

Text. Writer `writeP1(record)` in `lib/js/PROD/ephtrk.js`; no reader.

## Input

A Record whose every epoch also carries geodetic coordinates and mean elements (`TrackingRecord`):

| Epoch field | Content | Unit |
| --- | --- | --- |
| `geodetic.latitude`, `geodetic.longitude`, `geodetic.height` | geodetic coordinates | deg, deg, km |
| `meanElements.meanMotion` | mean motion | rev/day |
| `meanElements.eccentricity` | eccentricity | unitless |
| `meanElements.inclination`, `.raan`, `.argOfPericenter`, `.meanAnomaly` | angles | deg |
| `rev` | revolution number | integer |

A Record from `fromOcm` carries none of these: `epochs[i].geodetic` and `epochs[i].meanElements` are null for
every epoch and `epochs[i].rev` is null after the first. P1 of such a Record is refused with
`record-missing:epochs[<i>].geodetic`. P1 is produced from a Record extended with those per-epoch values (a typed
`$OCM` home for them, or a caller that adds them).

## Structure

In order: 12 header lines, 2 column-name rows, 4 lines per epoch, the trailer line `END`.

### Header lines

| Line | Token | Column | Format | Value |
| --- | --- | --- | --- | --- |
| 1 | `TITLE` | 1 | `A80` | `HEADER.MESSAGE_ID` |
| 2 | `VERSION` | 1 | `A80` | `PROVENANCE.PRODUCER` |
| 3 | `GRAVITY_PATH` | 25 | `A56` | `PERTURBATIONS.GRAVITY_MODEL` |
| 4 | `BUFFER_SIZE` | 25 | `I8` | the number of epochs |
| 5 | `RUN_MODE` | 25 | `A16` | the Record's theory: `ORB_AVERAGING`, else the mean element set's theory |
| 6 | `COMPATIBILITY_FLAGS` | 25 | `A16` | `METADATA.TIME_SYSTEM` |
| 7 | `OUTPUT_COORDINATE_SYSTEM` | 25 | `A16` | `TRAJ_REF_FRAME` |
| 8 | `PARTIALS_FLAG` | 25 | `L1` | `Y` when the Record carries per-epoch sensitivities, else `N` |
| 9 | `START` | 25 | `S18` | the first epoch |
| 10 | `STOP` | 25 | `S18` | the last epoch |
| 11 | `INTERVAL` | 25 | `F12.6` | the grid step in minutes; 0 for one epoch |
| 12 | `OBJECT` | 1 | `A80` | `METADATA.OBJECT_DESIGNATOR`, one blank, `METADATA.OBJECT_NAME` |

Lines 3 to 11 carry the token's name as a key (`A24` at column 1) and the value at column 25. The key
`OUTPUT_COORDINATE_SYSTEM` is 24 characters and fills its field, so no blank separates it from its value.

### Column-name rows

Row 1 names the line-1 tokens of an epoch block; row 2 names the line-2 and line-3 tokens, two tokens that share a
start column joined by `/`. A text or calendar token's name starts at the token's start column; a numeric token's
name ends at the token's last column.

### Epoch block

| Line | Token | Column | Format | Unit | Value |
| --- | --- | --- | --- | --- | --- |
| 1 | `MSE` | 16 | `F12.6` | min | minutes from `EPOCH_TZERO` |
| 1 | `POSX`, `POSY`, `POSZ` | 32, 50, 65 | `F15.8` | km | position, trajectory frame |
| 1 | `VELX`, `VELY`, `VELZ` | 81, 97, 113 | `F16.9` | km/s | velocity, trajectory frame |
| 2 | `DATE` | 2 | `S18` | UTC | the epoch |
| 2 | `LAT`, `LON` | 21, 37 | `F15.8` | deg | geodetic latitude, longitude |
| 2 | `HEIGHT` | 53 | `F15.6` | km | geodetic height |
| 2 | `REV` | 69 | `I8` | | revolution number |
| 3 | `N` | 21 | `F15.9` | rev/day | mean motion |
| 3 | `E` | 37 | `F15.10` | | eccentricity |
| 3 | `I`, `NODE`, `OMEGA`, `M` | 53, 69, 85, 101 | `F15.8` | deg | inclination, node, argument of pericenter, mean anomaly |
| 4 | `S1`, `S2`, `S3` | 21, 37, 53 | `%+14.6E` | km | UVW position sigmas |
| 4 | `S4`, `S5`, `S6` | 69, 85, 101 | `%+14.6E` | km/s | UVW velocity sigmas |

Line 1 equals the P2 row of the same epoch without its label; line 4 equals the P4 row of the same epoch.

`POSZ` starts at column 65, the column after `POSY`'s last; a `POSZ` that fills its 15 columns (-10000 km or
below, or 100000 km or above) leaves no blank between the two fields. `VELX`, `VELY` and `VELZ` are adjacent the
same way. Read P1 by column, not by blank-separated words.

## Frame, ordering, epoch

State: the Record's trajectory frame, cartesian. Sigmas: UVW at each epoch's own position and velocity, the square
roots of the covariance state-block diagonal. Epochs in Record order on a uniform grid; a grid that is not uniform
is refused. Epoch: minutes from `EPOCH_TZERO` (`MSE`) and the UTC calendar form (`DATE`, `START`, `STOP`).

## Refusal codes

| Code | Condition |
| --- | --- |
| `record-missing:HEADER.MESSAGE_ID` | no message id |
| `record-missing:PROVENANCE.PRODUCER` | no tool version |
| `record-missing:PERTURBATIONS.GRAVITY_MODEL` | no gravity model |
| `record-missing:ORB_AVERAGING` | no theory |
| `record-missing:METADATA.TIME_SYSTEM` | no time system |
| `record-missing:TRAJ_REF_FRAME` | no trajectory frame |
| `record-missing:METADATA.OBJECT_DESIGNATOR` | no object designator |
| `record-missing:METADATA.OBJECT_NAME` | no object name |
| `record-missing:STATE_DATA` | no states |
| `record-missing:COVARIANCE_DATA` | no covariance |
| `record-missing:epochs[<i>].geodetic` | epoch i has no geodetic coordinates |
| `record-missing:epochs[<i>].rev` | epoch i has no revolution number |
| `record-missing:epochs[<i>].meanElements` | epoch i has no mean elements |
| `epoch-grid` | the epochs are not on a uniform grid at `F12.6` resolution |
| `field-width:P1.<token>` | a value does not fit its token's field |
| `field-overlap` | two fields of a line overlap |
| `frame-degenerate` | an epoch's position and velocity define no UVW frame |
| `cov-size` | the covariance does not have `COV_SIZE` dimension |
